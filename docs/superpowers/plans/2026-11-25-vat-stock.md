# Shared VAT Stock Implementation Plan

> Execute inline, task by task, preserving the existing workspace and unrelated changes.

**Goal:** Add total/available VAT columns without adding user-driven Sheets reads.

**Architecture:** Existing worker publishes one raw-cell bundle to PostgreSQL with a lease and durable five-minute scheduling. VAT consumers parse the shared bundle; the product report enriches its rows before sorting/pagination/export.

**Tech Stack:** Node 22, CommonJS, Express, PostgreSQL, vanilla JavaScript, node:test/PGlite/JSDOM.

**Spec:** `docs/superpowers/specs/2026-11-25-vat-stock-design.md`.

## Global Constraints
- Preserve VAT allocation algorithms and source matching precedence.
- No new dependency, service, client framework or direct web Sheets fallback.
- Preserve I/O numeric zeros and negatives, unknown as null, actual snapshot age.
- No deployment or live migration in this change; stage rollout documentation.

Interfaces: `readVatSnapshot({pool, forceRefresh})` returns `{records, loadedAt, stale}`; `readSnapshotRecords(source)` reads cached raw cells; `refreshVatSnapshot({pool, readValues, now})` claims persisted schedule, validates and atomically publishes.
